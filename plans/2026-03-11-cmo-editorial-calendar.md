# ACE CMO Editorial Calendar

Date: 2026-03-11
Owner: CMO

## Objective

Turn the existing ACE message and campaign strategy into a publishing system Dan
can actually run from March 16, 2026 through April 10, 2026.

The goal is not more content. The goal is a repeatable sequence that:

- sharpens the category message
- turns each week into one proof-backed campaign
- converts attention into tracked clicks, setup intent, and design-partner leads

## Operating Rule

Every content unit must answer four questions before it ships:

1. What single idea is this teaching?
2. What proof asset makes that idea believable?
3. What one destination should the click go to?
4. What metric decides whether the post worked?

If any of those are unclear, the post is not ready.

## Core Weekly Rhythm

Monday:

- publish the category or thesis post
- point to the primary repo destination

Wednesday:

- publish the proof artifact
- reply manually to every high-signal builder response

Friday:

- publish the adoption or call-to-action post
- route strong responders into the design-partner funnel

Tuesday and Thursday:

- run reply distribution on adjacent conversations
- send DMs to qualified responders
- log tracked-link and conversation results

## Asset Dependency Map

The calendar only works if these assets are shipped in order:

1. `README.md` opening tightened before March 16
2. tracked-link system live before March 16
3. demo clip or still-image proof before March 18
4. delta explainer or doc section before March 23
5. example-driven adoption doc before April 1
6. design-partner logging system active before April 6

If an asset slips, do not publish a weaker substitute. Move the related post and
use a different proof-backed unit that week.

## Content Multiplication Rules

Each major post must create follow-on units:

- 1 anchor post or thread
- 2 short derivative posts
- 3 reply-bank variants
- 1 DM follow-up sequence
- 1 note about objections or language that should feed the next week

This keeps the content engine compounding instead of forcing a fresh idea every
day.

During governed launch weeks, a derivative unit does not have to be a net-new
public post. It can ship as reply distribution, DM follow-up, or another logged
follow-on touch when that is the safer way to preserve tracked-link discipline.

## Weekly Review Loop

Every Friday, log:

- which posts shipped
- tracked destination for each post
- impressions
- engagement rate
- outbound clicks
- high-signal replies
- DMs started
- qualified prospects
- setups started
- setups completed

Then make one decision for the next week:

- double down on a strong hook
- fix a weak CTA
- improve a proof asset
- change the destination if clicks are high but setup intent is low

## Decision Rules

If impressions are high but clicks are low:

- the hook is interesting but the product is still unclear
- tighten the category line and CTA

If clicks are high but setup starts are low:

- the conversion surface is weak
- prioritize README, MCP docs, or example improvements

If setup starts are high but completion is low:

- the adoption path is too hard
- prioritize onboarding docs, demo clarity, and product friction fixes

If serious replies are strong:

- move those people into the design-partner engine within 24 hours
